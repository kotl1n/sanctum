# Sanctum

Новый экспериментальный режим **без TCP-порта**: [Sanctum Portless](docs/PORTLESS.md). Rust-адаптер обрабатывает сообщения Desktop через stdin/stdout, shell-wrapper восстанавливает оригиналы локально и очищает вывод, а таблицы соответствий сохраняются с шифрованием отдельно для каждого чата. Для неявного текстового контекста подготовлен [патч backend Codex 0.159.0](native/codex-0.159.0/README.md): проверка полного тела Responses-запроса перед сжатием и отправкой. Это отдельная сборка backend, которая нужна в дополнение к плагину.

[Результаты проверок и оставшиеся ограничения](docs/VALIDATION_NATIVE.md).

Native-режим установлен на этом компьютере. Реальный тест через app-server с подпиской ChatGPT прошёл 17 октября 2026: агент получил `[IP-1] [IP-1] [IP-2]` вместо трёх исходных адресов, ход завершился без блокировки. Обычный ярлык **ChatGPT** теперь запускает Sanctum через пользовательский desktop entry. Для включения в окне приложения полностью выйдите из него, откройте **ChatGPT** или **ChatGPT — Sanctum** и создайте новый локальный чат.

## Ранее подготовленные варианты

**Блокирующий плагин без шлюза:** [Sanctum Prompt Guard](docs/PROMPT_GUARD.md) — отдельный Rust-плагин, который проверяет вводимый текст при нажатии «Отправить» и блокирует найденные секреты. Локальный сервер и настройка model provider ему не нужны. Готовый пакет находится в `dist/sanctum-prompt-guard`, исходники — `src/bin/sanctum-guard.rs` и `src/prompt_guard.rs`.

```bash
codex plugin marketplace add ./dist/sanctum-prompt-guard
codex plugin add sanctum-prompt-guard@sanctum-guard-dev
```

После установки требуется штатная проверка доверия к хуку в Codex (`/hooks` в CLI). [Инструкция и результаты](docs/PROMPT_GUARD.md).

## Вариант с локальным шлюзом

Локальный шлюз маскировки данных и **нативный плагин-компаньон для приложения Codex**. Исполняемый файл написан на Rust; для работы шлюза, хука и упаковки Python не нужен. Основная целевая среда этой сборки — Linux x86_64.

**Статус:** проверены автоматические тесты, локальный сквозной цикл и установленный Codex CLI с имитацией модели. Реальная авторизация через подписку ChatGPT в Desktop пока не проверена. Установка плагина сама по себе не перенаправляет трафик: шлюз запускается отдельно и выбирается как model provider.

## Сборка и демонстрация

Для сборки нужны Rust/Cargo 1.88+ и зависимости из Cargo.lock. Для запуска собранного бинарника Rust и Python не нужны.

```bash
cargo build --release --locked
./target/release/sanctum demo
```

Демо использует два сервера на `127.0.0.1`, синтетические данные и настоящую локальную команду `printf`. В OpenAI оно не обращается:

```text
1. Provider received: "Server [IP-1], email [EMAIL-1], password=[SECRET-1]"
2. Local tool executed: printf '%s' '11.111.111.11'
3. Local tool returned: 11.111.111.11
4. Follow-up provider received: "[IP-1]"
PASS: originals stayed local; native Rust gateway restored streamed tool arguments.
```

## Пакет плагина для Codex

```bash
./target/release/sanctum package
```

Команда создаёт новый каталог `dist/sanctum-rust` с локальным marketplace и готовым плагином. Внутри `plugin/bin/sanctum` находится копия исполняемого файла, а SessionStart-хук вызывает этот же бинарник с аргументом `session-start`. Python-скриптов в пакете нет. Поверх существующего каталога упаковка не выполняется: для следующей сборки задайте другой `--output`.

```text
dist/sanctum-rust/
  .agents/plugins/marketplace.json
  README.txt
  plugin/
    plugin.json
    .codex-plugin/plugin.json
    hooks/hooks.json
    bin/sanctum
```

Установка подготовленного пакета:

```bash
codex plugin marketplace add ./dist/sanctum-rust
codex plugin add sanctum-rust@sanctum-rust-dev
```

После установки перезапустите приложение и пройдите штатную проверку доверия хука в Codex. Пакет собран для архитектуры текущего компьютера. Эта версия упаковки и команды хука проверяются для Linux; сборки для macOS и Windows не подготовлены.

Хук объясняет агенту смысл заглушек и необходимость сохранять их в аргументах. Он не перехватывает сообщения. Bundled hooks и их доверие описаны в [официальной документации плагинов](https://developers.openai.com/plugins/build/plugins); публичный каталог сейчас не принимает пакеты с такими хуками.

## Подключение локального шлюза к Desktop

1. Подготовьте отдельные приватные файлы Rust-версии:

   ```bash
   ./target/release/sanctum prepare
   ```

   Создаются `~/.config/sanctum-rust/connection.json` и `codex.fragment.toml` с правами `0600`. В них находится локальный ключ шлюза. Настройки и сохранённая авторизация Codex этой командой не меняются. Повторная подготовка поверх существующих файлов запрещена.

2. Запустите процесс шлюза в отдельном терминале:

   ```bash
   ./target/release/sanctum serve
   ```

   При необходимости укажите собственную политику вне репозитория:

   ```bash
   ./target/release/sanctum serve --policy /private/path/sanctum.policy.local.json
   ```

3. Сохраните копию пользовательских настроек Codex. Объедините значения из сгенерированного `codex.fragment.toml` с существующей конфигурацией, не дублируя таблицы. Фрагмент выбирает `model_provider = "sanctum_rust"`, адрес `127.0.0.1`, `wire_api = "responses"`, `requires_openai_auth = true`, отключает WebSocket и hosted web search. Он не выбирает другую модель и не меняет sandbox или правила согласования команд. Файл с локальным credential должен оставаться приватным.

4. Перезапустите Desktop и начните новый чат **с синтетическими данными**. Поддержку этого маршрута конкретной сборкой приложения и типом подписки необходимо проверить до использования реальных секретов.

Маршрут с ChatGPT-авторизацией через gateway описан OpenAI для рабочих пространств: [ChatGPT through a gateway](https://learn.chatgpt.com/docs/enterprise/sign-in-with-chatgpt-through-a-gateway). Шлюз передаёт provider Authorization и account routing identity на фиксированный HTTPS endpoint `chatgpt.com/backend-api/codex`. Это авторизация пользователя, а не анонимный доступ к OpenAI. Сам Rust-порт не подтверждает, что Desktop направляет через него весь свой трафик.

Остановка — Ctrl+C. Для отката восстановите исходные настройки провайдера и `web_search`, удалите добавленную таблицу `model_providers.sanctum_rust`, затем перезапустите приложение. Таблицы замен живут в памяти процесса и теряются после остановки: продолжение прежних чатов после перезапуска шлюза пока не поддерживается.

Для отдельного API-режима существует `prepare --mode openai --directory /private/path/separate-state`, затем `serve --connection /private/path/separate-state/connection.json`. Он использует `OPENAI_API_KEY` на стороне Codex и `api.openai.com/v1` на стороне шлюза; это отдельная оплата API, а не подписка ChatGPT.

## Что переносится через шлюз

```text
Сообщение / фрагмент файла / вывод инструмента
  → Rust: оригиналы заменяются заглушками
  → модель: [IP-1], [EMAIL-1], [SECRET-1]
  → Rust: аргументы локального инструмента восстанавливаются
  → Codex выполняет инструмент с оригиналами
  → его результат снова маскируется перед следующим запросом
```

Распознаются валидные IPv4/IPv6, email, пароли и токены в именованных JSON-полях и присваиваниях, Bearer/Basic credentials, URL userinfo, некоторые форматы ключей OpenAI/Anthropic/GitHub/AWS/Slack, PEM private keys и явно заданные строки компании. Уже обнаруженные значения повторно скрываются и без подписи `password=`. JSON-ключи и сериализованные JSON-строки тоже обрабатываются; дублирующиеся ключи отклоняются.

Формат локальной политики совместим с Python-прототипом:

```json
{
  "literals": ["конкретный секрет", "internal.company.example"],
  "max_entries": 10000
}
```

Таблица соответствий разделена по сессиям. Для идентификатора используются заголовок Codex `session_id`, `X-Sanctum-Session` или `prompt_cache_key`; требуется неперсональная строка длиной 8–128 из букв, цифр, `_` и `-`. Неизвестные буквальные примеры `[IP-1]` во входном тексте резервируются до генерации новых обозначений. При исчерпании лимита таблицы не вытесняются — запрос отклоняется.

Восстановление поддерживает JSON function calls, custom `apply_patch` и code mode `exec`. Потоковый текст передаётся постепенно; аргументы каждого инструмента буферизуются отдельно до получения полного JSON. Учтены разрывы заглушек, JSON escaping и UTF-8 между сетевыми пакетами. Обычный текст ответа остаётся с заглушками. Известный provider encrypted reasoning разрешён для точного replay; неизвестные opaque blobs отклоняются.

## Текущие ограничения

- Это псевдонимизация с детекторами, а не полное распознавание персональных данных. Произвольные пароли без контекста, имена, телефоны, неизвестные форматы и обфускация могут быть пропущены. Возможны ложные срабатывания и изменения структуры исходного кода.
- Обрабатывается только текстовый HTTP JSON/SSE Responses. Вложения, изображения, аудио, hosted tools, background и server-side continuation отклоняются. WebSocket не поддерживается.
- Оригиналы с кавычками, пробелами, `$`, управляющими символами и другими небезопасными для подстановки знаками не вставляются автоматически в shell/code. Для них подходят структурированные аргументы локального инструмента. Произвольные команды с любыми паролями пока не поддерживаются.
- Gateway слушает только `127.0.0.1`, требует отдельный ключ, отклоняет browser Origin, не следует HTTP redirects и не использует ambient HTTP proxy. Cookies и посторонние заголовки не передаются. Тексты ошибок и credentials не журналируются. Локальный ключ и provider bearer дополнительно исключаются из тела контекста, если попали туда как текст.
- Шлюз не охватывает отдельные соединения MCP, плагинов, браузера, команд, аналитики или синхронизации. Восстановленные значения доступны локальному Codex и могут попасть в его transcript. Защита от намеренной эксфильтрации агентом с shell-доступом и корпоративное принуждение к сетевому маршруту не реализованы.
- Владельцы строк в таблице секретов очищаются при освобождении памяти через `zeroize`. Это не обещание отсутствия копий в сетевых, JSON-буферах, swap или дампах процесса.

## Остальные команды

```bash
printf '%s\n' 'host=11.111.111.11 password=synthetic-only' | ./target/release/sanctum redact
./target/release/sanctum --help
```

`redact --vault /private/path/session.vault.json` явно сохраняет **незашифрованную** таблицу с правами `0600`. `restore --vault ...` восстанавливает stdin локально. По умолчанию таблица на диск не записывается. `prompt-guard` — отдельный блокирующий хук; он не включён в пакет и не заменяет прозрачную обработку шлюзом.

## Проверки и исходники

```bash
cargo test --locked --all-targets
cargo clippy --locked --all-targets -- -D warnings
cargo fmt --all -- --check
cargo test --locked --lib codex_transport -- --ignored --nocapture
```

Последняя команда требует установленного Codex CLI, использует синтетический ключ, временную конфигурацию и имитацию модели. Сам клиент может делать фоновые запросы вне model provider, поэтому это не проверка полного сетевого покрытия Desktop. Полный статус — в [проверке Rust-версии](docs/RUST_VALIDATION.md).

Основной код: `src/redaction.rs`, `src/protocol.rs`, `src/gateway.rs`, `src/setup.rs`, `src/main.rs`. Cargo.lock фиксирует версии зависимостей. Исходная Python-реализация сохранена в `sanctum/`; её [описание](docs/PYTHON_PROTOTYPE.md) и [результаты проверки](docs/VALIDATION.md) относятся к версии 0.1.0. Claude Code пока не подключён. Лицензия для коммерческого распространения ещё не выбрана.
