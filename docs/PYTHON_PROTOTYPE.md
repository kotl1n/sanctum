# Python-прототип Sanctum 0.1.0

Локальный прототип защиты текстового контекста AI-агентов. Основная цель — **Codex Desktop с авторизацией ChatGPT**, с маскировкой перед моделью и восстановлением аргументов перед локальными инструментами.

**Статус: экспериментальный шлюз и плагин-компаньон.** Офлайн-цикл проверен на тестовом сервере; также проверен установленный Codex CLI 0.153.4 с имитацией модели. Подключение Desktop к реальной подписке и отсутствие утечек по остальным каналам приложения **не проверены**. Установка одного плагина не включает защиту. Claude Code пока не реализован.

```text
Пользователь / файл / результат команды
                  ↓
          локальный Sanctum
  11.111.111.11 → [IP-1]        ← таблица остаётся в памяти
                  ↓
         запрос к модели OpenAI
                  ↓
       инструмент с [IP-1]
                  ↓
          локальный Sanctum
  [IP-1] → 11.111.111.11
                  ↓
       обычный инструмент Codex
                  ↓
    его вывод снова маскируется
```

## Быстрая проверка без ключей и интернета

Нужен Python 3.11+. У программы нет сторонних runtime-зависимостей. Из корня репозитория:

```bash
python3 -m sanctum demo
python3 -m unittest discover -s tests -v
```

Демонстрация запускает два сервера на `127.0.0.1`: Sanctum и имитацию провайдера. Она передаёт синтетические IP, email и пароль, получает потоковый вызов `printf`, выполняет строго заданный `argv`, затем отправляет его результат через шлюз. Она проверяет реальные HTTP-тела обоих запросов, а не только результат регулярного выражения. В OpenAI ничего не отправляется.

Ожидаемый результат:

```text
1. Provider received: Server [IP-1], email [EMAIL-1], password=[SECRET-1]
2. Local tool executed: printf '%s' '11.111.111.11'
3. Local tool returned: 11.111.111.11
4. Follow-up provider received: [IP-1]
PASS: originals stayed local across both requests; streamed tool arguments restored.
```

Для обычного CLI-вызова вне репозитория можно установить пакет в своё виртуальное окружение: `python3 -m pip install --no-build-isolation -e .`. Установка Python-пакета не меняет настройки Codex.

Дополнительная проверка установленного Codex CLI: `python3 scripts/check_codex_transport.py`. Она использует временную конфигурацию, синтетический credential и имитацию модели, проверяя обычный code mode, локальное исполнение и повторный запрос. Сам Codex при этом может обращаться к фоновым сервисам вне model provider; это не полностью изолированный сетевой тест. Подробности результатов — в [VALIDATION.md](VALIDATION.md).

## Что распознаётся

| Данные | Пример замены |
|---|---|
| Валидные IPv4 и IPv6 | `[IP-1]` |
| Email | `[EMAIL-1]` |
| Пароли и токены в именованных JSON-полях и присваиваниях | `[SECRET-1]` |
| Bearer/Basic credentials и URL userinfo | `[SECRET-1]` |
| Некоторые форматы OpenAI/Anthropic/GitHub/AWS/Slack ключей | `[KEY-1]` |
| PEM private keys | `[PRIVATE_KEY-1]` |
| Явно заданные строки компании | `[CUSTOM-1]` |

Нумерация стабильна внутри сессии и типа данных. При последующих запросах Sanctum распознаёт уже обнаруженный секрет и без подписи `password=`. Два прохода по запросу находят также ранее встреченную строку, секретность которой выяснилась из более позднего поля этого же запроса.

Это **псевдонимизация, не шифрование и не универсальное обнаружение персональных данных**. Имена людей, телефоны, произвольные пароли без контекста, обфускация, закодированные/сжатые строки и неизвестные форматы секретов могут остаться незамеченными. Возможны ложные срабатывания и нарушение структуры кода. Для известных критичных значений используйте локальную политику:

```json
{
  "literals": ["конкретный секрет", "internal.company.example"],
  "max_entries": 10000
}
```

Храните реальные политики вне репозитория. Пример в `examples/policy.json` содержит только синтетические значения.

## Экспериментальное подключение Codex Desktop + ChatGPT

Актуальная документация описывает [ChatGPT-авторизацию через gateway](https://learn.chatgpt.com/docs/enterprise/sign-in-with-chatgpt-through-a-gateway), в том числе `requires_openai_auth = true`, отдельную авторизацию шлюза и upstream `https://chatgpt.com/backend-api/codex`. Описанный там основной сценарий — управляемые рабочие пространства. Возможность использования локального провайдера в конкретной версии Desktop и с конкретным типом подписки требует отдельной проверки. Пример конфигурации ниже не подтверждает совместимость подписки.

1. Подготовьте локальные файлы подключения:

   ```bash
   python3 -m sanctum prepare
   ```

   Команда создаёт `~/.config/sanctum/connection.json` и `~/.config/sanctum/codex.fragment.toml` с правами `0600`. Повторная генерация поверх существующих файлов запрещена. В них находится локальный ключ доступа к шлюзу. ChatGPT-токены команда не читает. Настройки Codex она не изменяет.

2. Запустите шлюз в отдельном терминале из корня репозитория:

   ```bash
   python3 -m sanctum serve
   ```

   С собственной политикой:

   ```bash
   python3 -m sanctum serve --policy /absolute/path/to/sanctum.policy.local.json
   ```

3. Для активации сначала сохраните копию своих настроек Codex. Перенесите значения из сгенерированного фрагмента в пользовательскую конфигурацию, объединяя существующие ключи и таблицы TOML. Фрагмент содержит `model_provider = "sanctum"`, адрес loopback, `wire_api = "responses"`, `requires_openai_auth = true`, отключение WebSocket и hosted web search. Он не меняет выбранную модель, sandbox или политику согласования команд. Храните конфигурацию с локальным ключом в приватном файле; для корпоративного развёртывания используйте доставку ключа через `env_http_headers`.

4. Перезапустите Desktop. Используйте **новый чат и только синтетические данные**. Если провайдер не появился или вход по подписке не работает, верните исходные настройки. Прототип не переключается на прямое подключение при ошибке шлюза.

5. Прежде чем работать с реальными данными, требуется проверить именно вашу версию Desktop: первый запрос, полный SSE-ответ, вызов инструмента, результат команды, следующий запрос, compaction и ошибки. Наличие работающего `/health` и успешный офлайн-тест не доказывают, что приложение направляет все эти запросы через Sanctum. См. [требования к gateway](https://learn.chatgpt.com/docs/enterprise/gateway-compatibility).

Gateway принимает `/backend-api/codex/responses`, `/responses/compact` под этим же префиксом и `/models`. Для разделения таблиц используются заголовок Codex `session_id`, либо `X-Sanctum-Session`, либо `prompt_cache_key`. Идентификатор должен быть неперсональной строкой длиной 8–128 из букв, цифр, `_` и `-`. При отсутствии подходящего идентификатора запрос отклоняется.

Для отката восстановите исходный `model_provider`, связанные настройки `web_search` и удалите добавленную таблицу провайдера `sanctum`, затем перезапустите Desktop. Остановить шлюз можно через Ctrl+C. Таблицы соответствий при этом теряются: продолжать старые чаты через новый экземпляр шлюза пока не поддерживается.

API-режим для будущего тестирования: `python3 -m sanctum prepare --mode openai --directory /absolute/path/to/separate-state`. Он использует `OPENAI_API_KEY` на стороне Codex и `https://api.openai.com/v1` на стороне шлюза. Это отдельный режим оплаты API, не подписка ChatGPT.

## Плагин-компаньон

Исходники находятся в `plugins/sanctum-local/`. Локальный каталог `.agents/plugins/marketplace.json` описывает источник `sanctum-dev`. Подключить каталог можно из корня репозитория:

```bash
codex plugin marketplace add .
codex plugin add sanctum-local@sanctum-dev
```

Затем перезапустите Desktop и проверьте установку. Доверие bundled hooks проверяется самим Codex отдельно; установка плагина не означает доверия его хукам. Хук `SessionStart` объясняет агенту смысл заглушек и необходимость сохранять их в аргументах. **Он не перехватывает запросы и не подтверждает, что gateway включён.** За маскировку отвечает отдельный локальный процесс и настройка провайдера. Пакет с хуками предназначен для ручной установки; текущая документация исключает такие пакеты из публичного каталога. [Упаковка плагинов](https://developers.openai.com/plugins/build/plugins).

Дополнительный `scripts/prompt_guard.py` — самостоятельный блокирующий `UserPromptSubmit`-хук, не включённый по умолчанию. При обнаружении данных он отклоняет сообщение без вывода оригинала. Он нужен только для отдельного сценария блокировки, а не прозрачной замены. Семантика хуков и возможное продолжение при ошибках самого runtime описаны в [документации Codex](https://learn.chatgpt.com/docs/hooks).

## Границы текущей версии

- Только HTTP JSON Responses и SSE. WebSocket, background и server-side continuation отключены. Hosted tools, изображения, аудио, загрузки и ссылки на файлы отклоняются до отправки upstream. Нет распознавания PII в изображениях.
- В SSE поток текста передаётся постепенно. Аргументы каждого инструмента буферизуются отдельно до получения полного JSON и затем восстанавливаются. Итоговые tool items тоже содержат восстановленные значения. Обычный текст ответа остаётся с заглушками.
- Восстанавливаются function-call JSON, `apply_patch` и code mode `exec` custom input. Неизвестные custom tools с заглушками отклоняются. Для shell/code полей сложные оригиналы с пробелами, кавычками, `$`, обратными кавычками и прочими управляющими символами блокируются: безопасно восстановить их при любой придуманной моделью расстановке кавычек нельзя. Структурированные поля обычного локального инструмента поддерживают такие строки с корректным JSON escaping. Прозрачное выполнение **произвольных** команд с **любыми** паролями пока не реализовано.
- Уже известный encrypted reasoning, пришедший от провайдера в этой сессии, разрешён для точного replay. Неизвестные encrypted blobs отклоняются. Его содержимое Sanctum не расшифровывает.
- Таблица соответствий живёт в памяти процесса, отдельно для каждой сессии. Она не экспортируется через HTTP. После перезапуска нет восстановления старых таблиц. При исчерпании лимита новых записей/сессий запрос блокируется; существующие таблицы не вытесняются.
- Буквальные примеры `[IP-1]` и подобных обозначений, впервые встретившиеся во входном тексте, резервируются до генерации новых замен. Например, если `[IP-1]` уже использован в документации, реальный адрес получит `[IP-2]`. Заглушка, придуманная моделью и не известная как замена или буквальный пример этой сессии, блокирует восстановление инструмента.
- Gateway слушает только `127.0.0.1`, требует отдельный локальный ключ, отклоняет browser Origin, не следует redirect и не передаёт cookies/посторонние заголовки. Авторизационный токен ChatGPT/API и account routing identity необходимы провайдеру и не маскируются. Это не анонимизация пользователя перед OpenAI.
- Нет журналирования тел запросов и значений секретов. Ошибки upstream сохраняют HTTP-статус, но их тела не возвращаются, поскольку могут содержать входной текст. Нет telemetry Sanctum. Это не контролирует логирование самого Codex, ОС или инструментов.
- Настройка model provider не маршрутизирует весь трафик Desktop. MCP, внешние плагины, браузер, локальная сеть, аналитика, синхронизация и другие подключения требуют отдельной проверки и сетевой политики. Восстановленные команды и их оригинальный вывод доступны локальному клиенту и могут попасть в его transcript. Нельзя утверждать, что «ни один секрет не попадёт ни на один сервер OpenAI» на основании этого прототипа.
- Агент с shell-доступом имеет полномочия пользователя. Защиты от намеренной эксфильтрации через произвольные команды, чтения памяти/локальных конфигов или отключения шлюза здесь нет. Инструкции плагина не являются такой защитой. Корпоративное принуждение к маршруту, отдельный пользователь службы, OS sandbox и egress enforcement — отдельный этап.

## Локальная маскировка отдельного текста

```bash
printf '%s\n' 'server=11.111.111.11 email=demo@example.com password=synthetic-only' | python3 -m sanctum redact
```

При необходимости `redact --vault /private/path/session.vault.json` явно сохраняет соответствия в **незашифрованный** файл с правами `0600`, без перезаписи существующего файла. Команда `restore --vault ...` читает обезличенный текст из stdin и восстанавливает значения локально. По умолчанию CLI не сохраняет таблицу. Не помещайте vault или connection files в чат и не добавляйте их в Git.

## Коммерческая гипотеза

Проверять спрос стоит у команд, которые разбирают клиентские логи, конфигурации и инциденты в AI-агентах. Проверяемый результат пилота: что дошло до провайдера, сколько секретов пропущено, сколько обычных задач сломано и сколько времени занимает установка. Готовность платить пока не подтверждена.

Потенциально продаваемая часть — управляемое развёртывание, локальные политики, поддержка версий агентов, измеримая точность, безопасное восстановление и аудит без секретов. До продаж как средства корпоративной защиты нужны реальная квалификация Desktop, проверка остальных каналов, качественный набор размеченных данных и независимая оценка реализации. Публичную лицензию и условия коммерческого распространения в этом прототипе ещё не выбирали.
