# Sanctum для Claude Code

Плагин `sanctum-claude` защищает приватные данные в Claude Code только через хуки. Он не запускает прокси, не открывает сетевой порт и не меняет `ANTHROPIC_BASE_URL`. Нужна версия Claude Code с полем `updatedToolOutput` для PostToolUse и с `asyncRewake` для хуков; проверено на 2.1.309.

## Как это работает

| Событие | Что делает Sanctum |
| --- | --- |
| `SessionStart` | Сообщает модели, что значения вида `[EMAIL-1]` — локальные псевдонимы. |
| `UserPromptSubmit` | Если в запросе есть приватные данные, оригинал блокируется (`suppressOriginalPrompt`). Второй, фоновый обработчик с `asyncRewake` передаёт модели замаскированную копию: она приходит вместо запроса. |
| `PreToolUse` | Для Bash псевдонимы восстанавливает и выполняет `sanctum-guard run-command`, а вывод снова маскируется. Для Read, Grep, Glob, LS и PowerShell аргументы восстанавливаются через `updatedInput`. Сетевые инструменты, MCP и субагенты получают только псевдонимы. |
| `PostToolUse` | Вывод любого инструмента, включая MCP и субагентов, маскируется через `updatedToolOutput` с сохранением формы. После Write, Edit, MultiEdit и NotebookEdit псевдонимы в записанном файле заменяются исходными значениями. |
| `MessageDisplay` | Только на экране: псевдонимы в ответах модели заменяются исходными значениями серого цвета, по которому видно, что модель получила заглушку. Сохранённое сообщение и то, что видит модель, не меняются. В терминале используется цвет ANSI. Десктопное приложение показывает HTML как текст, поэтому там значение выводится серой формулой LaTeX: шрифтом формул, частями не длиннее 60 символов и без буквального `@`, иначе формула не распознаётся. Внутри кода значение выводится без цвета. Стиль задаётся переменной `SANCTUM_DISPLAY_STYLE`: `ansi`, `latex` или `plain`. |

Соответствия хранятся в том же зашифрованном хранилище, что и у Desktop, отдельно для каждого проекта (`CLAUDE_PROJECT_DIR`). Claude Code выдаёт новый `session_id` при возобновлении, форке и `/clear`, поэтому привязка к проекту сохраняет псевдонимы рабочими после этих действий, а также у субагентов. Без 24-часового обновления соответствия истекают, и старые псевдонимы перестают восстанавливаться.

При ошибке маскирования вызов инструмента запрещается, а вывод заменяется заглушкой той же формы. Исходные значения не попадают в ответы хуков, которые Claude Code сохраняет в журнал сеанса. Исключение: аргументы Read, Grep, Glob, LS и PowerShell, если в них есть псевдонимы.

## Сборка и установка

```sh
cargo build --release --locked --bin sanctum-guard
target/release/sanctum-guard package-claude --output dist/sanctum-claude
```

Каталог содержит маркетплейс `sanctum-local` с плагином `sanctum-claude`. В Claude Code выполните:

```
/plugin marketplace add /абсолютный/путь/dist/sanctum-claude
/plugin install sanctum-claude@sanctum-local
```

Политика распознавания лежит в `plugin/policy.json`. Переменная `SANCTUM_GUARD_POLICY` её переопределяет. Защиту выключает `sanctum-guard settings --enabled false`; это общая настройка с Desktop.

## Ограничения

- Защищается то, что проходит через хуки: запросы и вывод инструментов. Файлы `CLAUDE.md`, память, вывод навыков и системные вложения Claude Code передаёт модели без хуков.
- Маскирование вывода рассчитано на случайную утечку. Модель, которая намеренно преобразует значения (`xxd`, разворот строки, пробелы между символами), может их увидеть. Это подтвердил тест с сабагентом Haiku.
- `old_string` в Edit проверяется по файлу на диске до хуков, поэтому не должен содержать псевдонимов: модель привязывается к соседнему тексту или использует Write.
- Восстановление в Bash выполняется в отдельной оболочке: `cd` и переменные из такой команды не сохраняются между вызовами.
- Запрос с приватными данными приходит модели как системное напоминание от хука, а не как обычное сообщение. В интерфейсе вместо него показывается замаскированная копия.
- Детекторы дают ложные срабатывания на исходном коде и служебных идентификаторах. Для чувствительных проектов настройте политику.
