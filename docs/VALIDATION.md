# Проверка Sanctum 0.1.0

Дата: 2026-10-16. Среда: Linux, Python 3.14.7, Codex CLI 0.153.4.

## Подтверждено

- `python3 -m unittest discover -s tests -v`: 59 тестов. Детекторы, повторные значения, резервирование буквальных заглушек, custom literals, вложенный и сериализованный JSON, IPv6, лимиты, восстановление JSON escaping, запрет небезопасной подстановки в shell, SSE с разделёнными аргументами, параллельные tool calls, opaque replay, сетевые ошибки, отсутствие оригиналов в HTTP-телах, защита от попадания credentials шлюза и провайдера в контекст, разделение сессий и права файлов.
- `python3 -m sanctum demo`: полный цикл на двух loopback-серверах, со строго заданной локальной командой. Тестовый провайдер получает заглушки в исходном сообщении и в последующем результате инструмента.
- `python3 scripts/check_codex_transport.py`: установленный Codex CLI подключён к Sanctum и имитации Responses API в отдельной временной конфигурации. CLI получил SSE custom code-mode call, выполнил `printf` с восстановленным синтетическим IP, проверил его значение локально и вернул результат в следующий запрос. Тестовый endpoint получил маскированный результат и не получил исходный IP в телах запросов.
- Регистрация каталога `sanctum-dev` и установка `sanctum-local@sanctum-dev` через настоящий Codex CLI прошли в отдельной временной конфигурации. Это проверка упаковки; постоянная установка в профиль пользователя не выполнялась. Доверие и запуск хука внутри Desktop не проверены.

## Что это не подтверждает

Авторизация через реальную подписку ChatGPT, выбор локального провайдера конкретной сборкой Desktop, полное покрытие сетевого трафика приложения, работа с реальными проектами и точность обнаружения на промышленном корпусе ещё не проверены. Compaction-маршрут реализован, но отдельной проверки compaction настоящим клиентом пока нет. Тест реального CLI использует API-format adapter с синтетическим ключом, а не ChatGPT-auth adapter.

Во время проверки реального CLI наблюдался отдельный фоновый запрос клиента к каталогу плагинов OpenAI, завершившийся `401`. Он не шёл через model gateway. Тест не устанавливает, какие данные отправляются по другим каналам приложения; это подтверждает необходимость отдельного контроля egress перед обещаниями полной локальности.

Демонстрация и тесты используют только синтетические значения. Пользовательская конфигурация, сохранённая авторизация и текущий Desktop-процесс не менялись. Никакие реальные ключи не копировались в тестовую среду.

## Следующий критерий готовности

Для заявления о поддержке Desktop + ChatGPT нужна отдельная квалификация на синтетических данных: реальная авторизация, первый запрос, полная потоковая выдача, tool loop, следующий ход, compaction, перезапуск, обновление credential и ошибки. Нужны наблюдение фактических исходящих запросов и проверка остальных сетевых путей. После этого можно оценивать покрытие детекторов на размеченном наборе и тестировать пилот с компанией.
