# Проверки native-режима Sanctum

Платформа: Linux x86_64, Rust 1.98.0. Backend: Codex 0.159.0,
upstream commit `687a119f0fcaace47e1f1abcc77cec6c813fd6da` с локальным патчем.
Неизменённый code-mode-host взят из установленного Desktop 0.159.0;
контрольная сумма закреплена в native manifest.

## Sanctum

- `cargo test --locked --all-targets`: 74 passed, 3 ignored.
- `cargo clippy --locked --all-targets -- -D warnings`: passed.
- Release helper: полное JSON-тело обработано через stdin/stdout; исходные
  тестовые IP/email/пароль отсутствуют в ответе.
- Сквозной тест с обычным Codex 0.159.0: passed.
- Сквозной тест с native Codex 0.159.0 и release guard/adapter: passed.

Сквозной сценарий проверяет реальный app-server и локальный code-mode-host:
prompt/текстовое вложение → запрос модели → локальная команда → вывод → повторный
запрос модели. Дополнительные исходные данные находятся в AGENTS.md, настройках
и описании навыка. Модель получает заглушки; команда получает исходные IP,
включая IP, найденный только в неявном контексте. Проверен точный повтор
зарегистрированного reasoning в том же чате. При недоступном helper ход завершается
ошибкой без дополнительного запроса модели. WebSocket-capable provider работает
через проверяемый HTTP fallback. Sanctum-адаптер не имеет TCP/UDP-сокетов.

Имитация модели временно слушает loopback только в тесте. Используются отдельный
временный CODEX_HOME и вымышленные данные; платная модель не вызывается.

## Проверка через подписку — 17 октября 2026

`python3 scripts/check_subscription.py --run-subscription-request`: passed.
Проверен установленный adapter → установленная native-сборка app-server →
реальный OpenAI backend с авторизацией `chatgpt` текущего пользователя.
Создан временный локальный чат с вымышленным IP в AGENTS.md. Получен ответ `OK`,
событие расхода токенов и статус `completed`; инструменты не вызывались.
Четыре хука Sanctum включены и имеют статус `trusted`.
API-ключ и отдельная оплата API не использовались.

При проверке обнаружена несовместимость старого отдельного prompt guard с новыми
полями общей политики. Его исполняемый файл обновлён до текущего Rust guard с
сохранением определения хука, политики и доверия. Чистый текст с общей политикой
проходит, вымышленный пароль блокируется. Обновлён и локальный источник плагина;
старые бинарники сохранены в приватной резервной копии.
Скрипт обновления теперь проверяет и обрабатывает этот случай.

## Upstream Codex

`just test -p codex-http-client -p codex-api -p codex-cli -p codex-chatgpt`:
813 выполнено, 794 passed, 19 failed, 1 skipped. Два теста прошли после штатного
повтора nextest. Все четыре новых теста `sanctum_http::tests` прошли.

`just fix` для четырёх изменённых пакетов завершился успешно. После исправления
стиля новых файлов отдельная проверка
`just clippy -p codex-http-client -- -D warnings` прошла без предупреждений.
Финальный `just fmt` завершился успешно. Общие тесты после форматирования повторно
не запускались согласно инструкции upstream AGENTS.md.

Причины 19 сбоев:

- 13 тестов daemon/updater не смогли скопировать бинарник во временные каталоги:
  `Disk quota exceeded`. Несколько параллельных копий dev-бинарника по 741 MiB
  превышают квоту `/tmp`. Эти режимы stdio-адаптером запрещены.
- 6 проверок классификации TLS-ошибок/fallback расходятся с ожиданиями upstream
  в текущем окружении. Они вызывают неизменённый RouteAwareClientPool с
  reqwest::Request; код новой проверки модельного тела в этом пути не вызывается.

Общий набор upstream **не считается полностью прошедшим**. TLS-сбои не скрыты
от результата и не исправлялись изменением сетевой безопасности Codex.

## Практическая граница

Дополнительная проверка 17 октября 2026: пользовательское сообщение с двумя разными вымышленными IP, один из которых повторён, обработано установленным adapter/backend через реальную подписку. Агент ответил `[IP-1] [IP-1] [IP-2]`, статус хода — `completed`, инструменты не вызывались; четыре хука включены и доверены. Это проверяет именно замену текста пользовательского сообщения без остановки генерации. Release-сборка повторно прошла `check_portless.py --release --native-boundary`.

Проверка подписки выполнена через app-server, а взаимодействие с самим окном
Desktop после перезапуска ещё не проверено. Нужен полный выход и запуск через
обычный ярлык **ChatGPT** (теперь он запускает Sanctum) или **ChatGPT — Sanctum**,
затем новый локальный чат. Системный бинарник и настройки
авторизации/провайдера не заменяются.
Это экспериментальная интеграция с фильтром текстового Responses-контекста,
не DLP всего трафика Desktop. Ограничения описаны в [PORTLESS.md](PORTLESS.md).
