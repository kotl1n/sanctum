# Проверка Sanctum Rust 0.2.0

Дата: 2026-10-16. Среда: Linux x86_64, rustc/Cargo 1.98.0, Codex CLI 0.153.4. Исходники Rust находятся в `src/`; зависимости зафиксированы в Cargo.lock.

## Результаты

- `cargo test --locked --all-targets`: **42 теста прошли**, отдельный тест с внешним Codex CLI помечен ignored для обычного запуска. Проверены детекторы, Unicode, IPv6, пунктуация, пересечение секретов, резервирование заглушек, JSON escaping и дубли ключей, сериализованный JSON, лимиты, unsafe shell/code, opaque replay, изоляция сессий и сетевые запросы.
- `cargo test --locked --lib codex_transport -- --ignored --nocapture`: **отдельный тест с настоящим Codex CLI прошёл**. Клиент использовал временную конфигурацию, синтетический ключ и имитацию модели. Получил SSE code-mode вызов, выполнил локальный `printf` с оригинальным синтетическим IP, проверил его значение в локальном коде и отправил результат через Rust-шлюз. Тестовый upstream получил заглушку. Исходный IP отсутствовал в телах обоих модельных запросов.
- `cargo clippy --locked --all-targets -- -D warnings`: прошёл без предупреждений.
- `cargo fmt --all -- --check`: прошёл.
- `cargo build --release --locked`: release-бинарник успешно собран.
- `./target/release/sanctum demo`: сквозная проверка на двух loopback-серверах прошла. Эта демонстрация обращений в OpenAI не делает.
- `./target/release/sanctum package`: создан пакет `dist/sanctum-rust` с marketplace, манифестами, hook-конфигурацией и копией release-бинарника. В пакете нет Python-скриптов; хук вызывает `bin/sanctum session-start`.
- Пакет зарегистрирован и установлен настоящими командами `codex plugin marketplace add` и `codex plugin add sanctum-rust@sanctum-rust-dev` в отдельном временном профиле. Установленный бинарник успешно выполнил `session-start` и вернул ожидаемый JSON.

## Сборка

Артефакт `dist/sanctum-rust/plugin/bin/sanctum` — stripped ELF x86_64 Linux, примерно 5,8 МиБ. Системные динамические зависимости: glibc, libm, libgcc_s и ELF loader. Python, Rust toolchain и OpenSSL для запуска не требуются. Совместимость со старыми glibc, другими архитектурами, macOS и Windows не проверена. Эта сборка не заявлена как полностью статическая или воспроизводимая побитово.

Архив: `dist/sanctum-rust-linux-x86_64.tar.gz`. Контрольная сумма архива записана в `dist/SHA256SUMS`. В архив не включаются пользовательские connection files, vault, политики с реальными секретами или сохранённая авторизация Codex.

## Что остаётся непроверенным

Авторизация через настоящую подписку ChatGPT в Desktop, доверие и запуск хука самим Desktop runtime, направление всех модельных запросов Desktop через шлюз, compaction настоящим клиентом, обновление credential, переподключение и все остальные сетевые каналы приложения. Проверка установленного CLI использовала API-режим со синтетическим credential, а не ChatGPT-авторизацию.

Запуск клиента с имитацией модели не изолирует его фоновые сервисные запросы. Они могут идти отдельно от model provider. Результат не доказывает, что ни один секрет не покинет компьютер по любому каналу приложения.

Корпоративное принуждение к маршруту, защита от намеренной эксфильтрации через shell, шифрование сохранённой таблицы и произвольная безопасная подстановка любых паролей в любую shell-команду не реализованы. Точность детекторов на промышленном размеченном корпусе не измерялась.

Пользовательская конфигурация, текущий процесс Desktop и сохранённая авторизация не изменялись. Оригинальный Python-прототип сохранён отдельно.
