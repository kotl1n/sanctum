# Sanctum Prompt Guard 0.1.0

Отдельный **Rust-плагин для проверки промпта при отправке**. Не запускает сервер, не открывает локальный порт и не меняет провайдера модели. Python и API-ключ для самого проверяющего процесса не нужны.

## Поведение

1. Пользователь пишет сообщение и нажимает «Отправить».
2. Codex вызывает локальный `UserPromptSubmit`-хук.
3. Чистый текст разрешается к обработке. При обнаружении данных возвращается `decision: block`.
4. Предупреждение содержит категории и количество разных значений, например `IP: 1, EMAIL: 1`. Исходные значения в предупреждение не включаются.
5. Пользователь исправляет текст и отправляет его снова.

Автозамена и подсветка внутри поля ввода не реализованы. Плагин также не восстанавливает заглушки в командах. Его назначение — остановить случайную отправку найденных данных во вводимом промпте.

## Установка готового пакета

Для Linux x86_64 подготовлены:

- Каталог `dist/sanctum-prompt-guard/`.
- Архив `dist/sanctum-prompt-guard-linux-x86_64.tar.gz`.
- Контрольная сумма в `dist/SHA256SUMS`.

Из корня репозитория:

```bash
codex plugin marketplace add ./dist/sanctum-prompt-guard
codex plugin add sanctum-prompt-guard@sanctum-guard-dev
```

Если используется распакованный архив, передайте `marketplace add` абсолютный путь к каталогу `sanctum-prompt-guard`, содержащему `.agents/plugins/marketplace.json`.

Перезапустите приложение. **Установленного плагина недостаточно: Codex должен доверять его хуку.** В CLI откройте `/hooks`, найдите `sanctum-prompt-guard`, проверьте команду и разрешите этот хук штатным способом. Пока хук не доверен, Codex его пропускает. CLI и Desktop должны использовать один профиль конфигурации, чтобы запись доверия действовала в обоих клиентах. [Документация доверия к хукам](https://learn.chatgpt.com/docs/hooks#review-and-trust-hooks).

Сначала проверьте в новом чате на синтетических данных: обычный вопрос должен пройти, а `Check server 11.111.111.11` — быть заблокирован. Не вводите настоящий секрет для проверки установки. Отображение предупреждения зависит от клиента; backend выдаёт событие `hook/completed` со статусом `blocked` и текстом причины. В проверенной версии CLI режим `exec --json` завершает заблокированный ход с нулевым расходом токенов, но не печатает текст причины отдельным сообщением.

В пользовательский профиль плагин автоматически не устанавливался. Тесты установки и доверия проводились в отдельных временных профилях.

## Сборка и упаковка

```bash
cargo build --locked --release --bin sanctum-guard
./target/release/sanctum-guard demo
./target/release/sanctum-guard package
```

`package` требует новый выходной каталог. При повторной упаковке укажите другой `--output`, чтобы не перезаписать предыдущую сборку.

```text
sanctum-prompt-guard/
  .agents/plugins/marketplace.json
  README.txt
  plugin/
    .codex-plugin/plugin.json
    hooks/hooks.json
    policy.json
    bin/sanctum-guard
```

Пакет использует только совместимый манифест `.codex-plugin/plugin.json`. В установленном Codex 0.153.4 обнаружено, что присутствие portable `plugin.json` в корне этого пакета мешает загрузке bundled hooks. Установка в таком случае отображалась как успешная, но `hooks/list` возвращал пустой список. В итоговой упаковке корневого `plugin.json` нет; загрузка и выполнение хука проверены.

## Детекторы и свои секреты

Используются локальные детекторы IPv4/IPv6, email, именованных паролей и токенов, некоторых форматов ключей, JWT, URL credentials и private PEM keys. JSON-промпты и вложенные сериализованные JSON-строки также проверяются. Буквальные примеры заглушек вроде `[IP-1]` разрешены.

Для известных секретов компании можно задать приватный JSON-файл:

```json
{
  "literals": ["известный-секрет-компании"],
  "max_entries": 10000
}
```

Укажите путь через `SANCTUM_GUARD_POLICY` в окружении процесса Codex. Для CLI это, например, `SANCTUM_GUARD_POLICY=/private/path/policy.json codex`. Для Desktop переменная должна быть доступна самому процессу приложения при запуске. Отсутствующая или повреждённая явно заданная политика приводит к блокирующему ответу проверяющего процесса. В пакете находится пустая пользовательская политика; штатные детекторы работают независимо от неё.

## Проверки

Дата: 2026-10-16. Linux x86_64, rustc/Cargo 1.98.0, Codex CLI/app-server 0.153.4.

- Основной набор Rust: 51 тест, включая 9 тестов нового checker и пакета.
- Дополнительно запущены два теста установленного плагина через настоящие Codex CLI и app-server. Они помечены ignored при обычном запуске, потому что требуют установленного клиента.
- CLI-тест: два чистых промпта достигли имитации модели; промпты с IP, email и паролем не добавили ни одного запроса к ней. Шлюз Sanctum не запускался.
- App-server-тест: установленный хук обнаружен как `userPromptSubmit`, имеет статус доверия `trusted`; при отправке синтетического IP получено `hook/completed` со статусом `blocked`. В предупреждении есть `IP: 1`, самого адреса нет. Запросов к модели — ноль.
- В обоих интеграционных тестах проверена идентичность установленного бинарника и hook-конфигурации подготовленному артефакту. Временный профиль доверял только точному хешу этого хука. Флаги обхода доверия не используются; пользовательский профиль и его доверие не менялись.
- Clippy с `-D warnings`, форматирование, release-сборка, упаковка и офлайн-демо проверяются отдельно.

```bash
cargo test --locked --all-targets
cargo test --locked --test rust_guard_codex -- --ignored --nocapture
cargo clippy --locked --all-targets -- -D warnings
cargo fmt --all -- --check
```

В интеграционных тестах порты открывает только имитация модельного сервера для измерения количества запросов. Проверяющий плагин портов не открывает. Сам Codex может обращаться к фоновым сервисам вне модельного провайдера; эти тесты не изолируют все сетевые пути приложения.

## Ограничения

Проверяется только поле `prompt`. Последующее чтение файлов, вывод команд, вложения, другие хуки и внешние сервисы этим плагином не защищаются. Промпт может сохраняться самим клиентом в локальной истории даже при блокировке. Отдельная проверка интерфейса открытого Desktop с реальной подпиской пока не проводилась; проверен его серверный протокол на установленной версии app-server.

Детекторы могут пропускать неизвестные форматы и давать ложные срабатывания. Произвольный пароль без контекста и имена людей не распознаются универсально. Любой валидный IP, включая localhost, считается потенциально чувствительным. Если процесс checker смог обработать ошибку, он возвращает блокирующее решение; запуск, отключение, доверие, краш или тайм-аут самого хука остаются под управлением Codex runtime. Это не принудительная корпоративная DLP-политика.

Чтобы отключить проверку, отключите хук через `/hooks` либо удалите плагин штатной командой `codex plugin remove sanctum-prompt-guard@sanctum-guard-dev`. Настройку model provider менять не требуется.
