# Sanctum Portless — экспериментальный режим без TCP-порта

Rust-адаптер `sanctum-codex` запускает настоящий `codex app-server` и обрабатывает его JSON-RPC через stdin/stdout. Сам Sanctum не создаёт TCP/UDP-listener и не меняет модельного провайдера. Для реальной модели остаётся обычное исходящее HTTPS-соединение Codex и авторизация ChatGPT.

Замены выполняет адаптер до передачи текста backend, а не обычный UserPromptSubmit-хук. При прямом запуске приложения без адаптера установленный хук блокирует исходный текст. На этом компьютере обычный ярлык ChatGPT настроен на запуск через адаптер.

## Компоненты

- Текст `turn/start` и `turn/steer` автоматически заменяется заглушками до передачи backend.
- В native-режиме отдельная сборка Codex проверяет полное тело запроса модели перед сжатием и отправкой. Это закрывает текстовый контекст, который backend добавляет сам: AGENTS.md, инструкции, описания навыков и инструментов. Backend обращается к Rust-фильтру через трубы stdin/stdout. [Патч и сборка](../native/codex-0.159.0/README.md).
- `PreToolUse` оборачивает shell-команду локальным Rust-процессом. Он восстанавливает значения, выполняет команду и очищает оба потока вывода до возврата в Codex. Другие поддержанные локальные инструменты используют восстановление структурированных аргументов.
- `PostToolUse` проверяет текстовый JSON-результат, сохраняет новые соответствия и блокирует исходный результат и возвращает очищенный feedback при обнаружении данных. В code mode это может выглядеть как отклонённый вызов с очищенным выводом; shell-wrapper позволяет сохранить обычный результат без такого отклонения.
- Для каждого чата создаётся отдельная зашифрованная таблица XChaCha20-Poly1305 со случайным nonce. Записи привязаны к хешу идентификатора сессии через AEAD associated data. Ключ хранится отдельно в локальном файле `0600`, каталог `0700`; это не системная связка ключей и не защита от другого процесса того же пользователя.
- Модель видит заглушки, оригиналы остаются локально. Таблица переживает перезапуск процессов. Срок бездействия — 24 часа; просроченная таблица блокирует работу до явного удаления. После удаления начинайте новый чат: старые заглушки нельзя безопасно переиспользовать.

## Сборка

```bash
cargo build --locked --release --bins
./target/release/sanctum-guard package-portless
python3 scripts/build_native_backend.py
codex plugin marketplace add ./dist/sanctum-portless
codex plugin add sanctum-portless@sanctum-portless-dev
```

Нужно проверить и доверить три хука плагина через `/hooks`. Адаптер сам запрашивает `hooks/list` и отказывается начинать или продолжать ход, если требуемые хуки не включены и не имеют статуса `trusted`.

Для запуска Desktop задаются `SANCTUM_REAL_CODEX` — абсолютный путь к настоящему Codex, `CODEX_CLI_PATH` — абсолютный путь к `sanctum-codex`, `SANCTUM_STATE_DIR` — приватный абсолютный каталог состояния. `SANCTUM_GUARD_POLICY` задаёт приватный JSON с политикой для обоих процессов.

Для проверки окончательного запроса `SANCTUM_REAL_CODEX` должен указывать на сборку с native-патчем; также нужны `SANCTUM_NATIVE_REQUIRED=1` и `SANCTUM_NATIVE_HELPER` с абсолютным путём к `sanctum-guard`. Адаптер проверяет протокол backend перед запуском. Отсутствие helper, ошибка, неверный ответ или тайм-аут блокируют отправку. Используется HTTP Responses API; WebSocket переключается на этот маршрут штатным fallback Codex. Авторизация через ChatGPT остаётся в backend.

В native-запуске встроенный `web_search` отключается для этого процесса: hosted-вызовы не проходят через локальные хуки. Удалённый `--code-mode-host` запрещён; code mode использует локальный host со stdio. Это не меняет обычные настройки запусков без Sanctum.

Путь `CODEX_CLI_PATH` проверен в коде установленного приложения; это не обещание стабильного публичного API. Не заменяйте системный бинарник. Уже запущенное приложение не получает новое окружение: нужен отдельный запуск после полного выхода из приложения. Запуски CLI, кроме app-server stdio, адаптером не защищаются.

## Локальные команды

```bash
printf '%s' 'server 11.111.111.11' | sanctum-guard mask --session local-demo
sanctum-guard forget --session local-demo
```

`mask` выдаёт только очищенный текст. Аргументы и имена файлов не должны содержать реальные секреты; передавайте исходный текст через stdin.

## Детекторы

IP, email, именованные секреты, ключи/JWT/PEM, URL credentials, международные телефоны с `+`, карты с проверкой Luhn, документы/ФИО/телефоны в подписанных полях, внутренние домены `.internal/.local/.corp/.lan`. `personal_names` задаёт точные имена, `internal_domains` — домены компании, `patterns` — дополнительные регулярные выражения, `literals` — известные секреты.

## Граница защиты

Поддерживаются текстовые промпты и результаты локальных инструментов, прошедших хуки. Неподдержанные вложения, изображения и внешняя история отклоняются, а не отправляются как есть. Локальные текстовые `mention`/`skill` читаются и превращаются в очищенный текст до передачи backend; симлинки, бинарные и слишком большие вложения отклоняются. Возобновление старого незащищённого чата запрещено.

Обычный stdio-адаптер не видит окончательный запрос модели. Системный контекст закрывается только при подключённом native-патче; без него остаётся предварительная блокирующая проверка AGENTS.md/AGENTS.override.md с ограниченным покрытием.

Native-проверка обрабатывает всё текстовое JSON-тело Responses-запроса двумя проходами с общей таблицей замен. Непрозрачные изображения/файлы, hosted tools и server-side continuation запрещены. Зашифрованный reasoning разрешён только как точный повтор блока, полученного от провайдера в том же чате; другие непрозрачные блоки отклоняются. Вызов helper ограничен 8 MiB и 15 секундами. Операции, возвращающие новый непрозрачный контекст вне поддержанного Responses stream (например, отдельные режимы compaction), могут блокироваться при продолжении.

Это не контроль всего сетевого трафика Desktop: телеметрия, удалённые MCP/коннекторы и другие внешние сервисы требуют отдельной защиты. Реальный запрос через установленный app-server с подпиской ChatGPT проверен 17 октября 2026: ответ `OK`, событие расхода токенов, четыре доверенных хука. Само окно Desktop после перезапуска ещё не проверено. Подробности — в [отчёте](VALIDATION_NATIVE.md).

Восстановление shell/code допускает только значения, безопасные для буквальной подстановки; сложные секреты с кавычками/пробелами/управляющими символами блокируются. Неизвестные инструменты запрещены в этом режиме; взаимодействие с уже работающей shell-сессией имеет ограничения runtime. Shell-процесс буферизует stdout/stderr с ограничением 8 MiB на поток и временем 120 секунд; интерактивный stdin не поддерживается. Хуки, отключённые после начала хода, падения и тайм-ауты остаются под управлением Codex. Это не защита от намеренной эксфильтрации агентом с доступом к локальной файловой системе.

Детекторы могут ошибаться. Произвольный пароль и любое имя человека невозможно надёжно определить по одному только виду строки.

## Проверки

```bash
cargo test --locked --all-targets
cargo clippy --locked --all-targets -- -D warnings
python3 scripts/check_portless.py
python3 scripts/check_portless.py --codex /usr/lib/chatgpt/resources/codex
python3 scripts/check_portless.py --native-boundary --codex ./dist/sanctum-native-backend/codex
```

Интеграционный сценарий использует отдельный временный CODEX_HOME и настоящие Codex app-server 0.153.4/0.159.0. Только имитация модели временно слушает loopback. Сам адаптер не имеет TCP/UDP-сокетов (runtime может использовать безымянную Unix socketpair для сигналов); запросы модели проверяются на отсутствие исходных тестовых IP/email/пароля/телефона. Команда записывает исходный IP в локальный файл, затем читает другой файл с новыми секретами. Поддержанное текстовое вложение очищается, изображения/аудио блокируются. Платная модель в тесте не вызывается.

Дополнительный native-сценарий проверяет секреты в AGENTS.md, настройках и метаданных навыка, восстановление новой заглушки из этого контекста в локальной команде, точный повтор reasoning, fallback с WebSocket на HTTP и отказ без отправки при недоступном фильтре.

Отдельная проверка настоящей подписки запускается явно:

```bash
python3 scripts/check_subscription.py --run-subscription-request
```

Она расходует токены подписки, использует установленный launcher и временный чат с вымышленными данными. Состояние замен временное; настройки авторизации и доверия не меняются. В вывод попадают только статусы проверки.

## Запуск на этом компьютере

После установки подготовлен отдельный ярлык **ChatGPT — Sanctum** и команда `~/.local/bin/sanctum-desktop`. Обычный ярлык **ChatGPT** также направлен на этот launcher через `~/.local/share/applications/chatgpt.desktop`; системный desktop entry сохранён. Полностью выйдите из текущего приложения, запустите любой из этих ярлыков и создайте новый локальный чат. Старые чаты, созданные без таблицы Sanctum, не возобновляются в защищённом режиме. Уже работающее окно не переключается на адаптер при повторном нажатии на ярлык.

17 октября 2026 проверен установленный launcher через реальную подписку: три вымышленных IP (первый повторён дважды) дошли до агента как `[IP-1] [IP-1] [IP-2]`; получен именно этот ответ, ход завершился со статусом `completed`. Все четыре хука доверены. Сквозная проверка release-сборки с имитацией модели также прошла. Пользовательский ярлык создан с резервной записью в `~/.codex/backups/sanctum-default-launch-20261017-091429-061098/`; раньше пользовательского `chatgpt.desktop` не было, поэтому для отката достаточно удалить только его и обновить desktop database.

Установлена отдельная native-сборка `~/.local/lib/sanctum/codex-0.159.0-native-79606dde3051/`. Резервная копия прежнего launcher и бинарников, включая старый отдельный prompt guard: `~/.codex/backups/sanctum-native-20261016-221621-197706/`. `receipt.json` и `legacy-receipt.json` фиксируют пути и контрольные суммы для восстановления. Обновлённый отдельный guard понимает расширенную политику; его прежнее определение блокирующего хука сохранено.

Готовые новые архивы: `dist/sanctum-portless-native-linux-x86_64.tar.gz`, `dist/sanctum-native-backend-linux-x86_64.tar.gz`, `dist/sanctum-prompt-guard-compatible-linux-x86_64.tar.gz`. Контрольные суммы — `dist/SHA256SUMS`. Прежние архивы сохранены отдельно.

Локальная политика находится в `~/.config/sanctum-portless/policy.json`, зашифрованное состояние — в `~/.local/state/sanctum-portless`. Пример собственных правил (все значения вымышленные):

```json
{
  "literals": ["company-secret-example"],
  "personal_names": ["Иван Примеров"],
  "internal_domains": ["company.example"],
  "patterns": ["EMP-[0-9]{5}"],
  "max_entries": 10000
}
```

Для удаления плагина: `codex plugin remove sanctum-portless@sanctum-portless-dev`. Затем удалите только созданные launcher/ярлык и отдельную сборку `~/.local/lib/sanctum`. Зашифрованное состояние и приватную политику удаляйте отдельно, если они больше не нужны. Провайдер модели, авторизация и системный бинарник не заменялись.
