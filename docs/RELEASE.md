# Проверка релиза

Целевая версия — **Sanctum 1.0.0**, включая все пакеты плагинов. Нативная интеграция закреплена на Codex 0.159.0; коммит, протокол и контрольные суммы находятся в `native/codex-0.159.0-context/manifest.json`. Изменение версии Sanctum само по себе не меняет эти контракты.

## Автоматические проверки

`.github/workflows/windows.yml` добавляет тесты и релизную сборку Sanctum на Windows MSVC, проверки Windows GNU через Docker/Wine и `cargo check` закреплённого нативного патча на MSVC. Задания ещё не запускались на GitHub. Проверка `cargo check` не подтверждает полную сборку или запуск нативной серверной части.

`.github/workflows/ci.yml` проверяет форматирование, Clippy, тесты Rust, установщик и упаковку Python, запускатель Node, синтаксис и оптимизированную сборку с проверкой персональных путей. Отдельные задания проверяют Rust 1.88 и соответствие нативного патча закреплённым контрольным суммам upstream. Проверка патча не заменяет полную сборку серверной части.

Тесты покрывают маскирование и восстановление, русский и английский языки, Unicode и границы SSE, изоляцию сеансов, повреждение хранилища, воспроизведение зашифрованной истории, сохранение схем, аргументы локальных инструментов, некорректный JSON, авторизацию шлюза, CLI, установку, удаление, откат, прерванные транзакции, конфликты изменённых файлов, согласованность версий и ошибки запускателя.

Тесты и вспомогательные исходники поставляются в архиве исходников для воспроизводимости. В установленный плагин попадают только необходимые исполняемые файлы, ресурсы интерфейса и средства управления. `target/`, `dist/`, временные файлы, ключи и локальные настройки исключены из Git и архива исходников.

## Нативная серверная часть

Закреплённая серверная часть ранее была полностью собрана локально на Linux с проверкой протокола. Полная сборка и запуск этой серверной части на Windows ещё не проверены. Упаковщик проверяет манифест, патч и контрольные суммы исполняемых файлов перед повторным использованием. Исходники upstream и оригиналы его лицензии и уведомлений включаются в комплект. Собственный код Sanctum должен проходить Clippy с `-D warnings`.

## Проверка полного комплекта

`tests/smoke_bundle.py` упаковывает настоящие релизные файлы и во временном домашнем каталоге проверяет установку, совместимость, включение, маскирование, локальное восстановление, отклонение неизвестных псевдонимов, инициализацию нативного app-server и удаление с сохранением изменённых настроек. Запрос к модели не отправляется; профиль пользователя не меняется. Следующая команда использует закреплённый профиль Linux.

```sh
python3 tests/smoke_bundle.py --backend dist/sanctum-context-backend --output dist/sanctum-1.0.0-check
```

Выходной каталог должен отсутствовать до запуска. Профиль совместимости должен соответствовать установленному Desktop.

## Перед публикацией

- Выполните команды проверки из README. После отправки коммита убедитесь, что GitHub Actions прошли на этом коммите.
- Сверьте версии пакетов, исполняемых файлов, путей установки и сформированных метаданных: 1.0.0.
- Проверьте текущие исходники, историю Git и архивы на учётные данные, настройки аккаунта, хранилища, результаты сборки и персональные пути.
- Публикуйте вместе с исполняемыми файлами соответствующие исходники Sanctum и upstream, патч, лицензии, уведомления и проверенные контрольные суммы.
- Создайте релизный коммит и тег только после проверки его состава. Адрес удалённого репозитория задаёт владелец проекта.

## Ручная проверка Desktop — ещё не завершена

Автоматические тесты не подтверждают готовность реального сеанса Desktop. До объявления стабильного релиза выполните на чистом профиле:

- Установку плагина из сформированного комплекта и явное доверие его хукам.
- Запуск через Sanctum, проверку совместимости, включение и отключение защиты.
- Реальный запрос к модели с синтетическими данными, подсветку поля ввода и корректность ответа.
- Сжатие и воспроизведение истории сеанса, полный перезапуск приложения.
- Восстановление команды, стандартного ввода, рабочего каталога и многострочного патча через настоящий локальный инструмент.
- Удаление и откат с сохранением изменённых настроек пользователя.

Используйте только синтетические данные. Зафиксируйте проверенную сборку Desktop, результат каждого сценария и коммит Sanctum. Пока эта проверка не завершена, комплект следует считать кандидатом на релиз. Установка файлов сама по себе не регистрирует плагин и не выдаёт доверие хукам.

## Язык и совместимость

Пользовательские описания, справка и сообщения Sanctum переведены на русский. Имена команд, JSON-поля, коды ошибок, идентификаторы протоколов и инструкции для модели сохраняются для совместимости. Оригиналы GPL и лицензий upstream не переводятся; юридически значим исходный текст.

Публикация на GitHub — отдельный шаг. Локальная проверка и упаковка не отправляют данные в удалённый репозиторий и не подтверждают успешный запуск GitHub Actions.

## Результат локальной автоматической проверки

- После добавления Windows на Linux пройдены 52 теста Rust, 22 теста Python и 5 тестов Node; оптимизированная сборка Linux выполнена.
- В Linux-контейнере с WineHQ 11 пройдены 56 Windows-тестов Rust, 22 теста Windows Python и Clippy для Windows GNU с `-D warnings`. Это не проверка настоящего Windows Desktop или MSVC.
- На настоящей Windows 11 Enterprise Eval 10.0.26300.9457 в VirtualBox пройдены 56 тестов Rust из исполняемых файлов Windows GNU, 22 теста Python, 5 тестов Node и проверка синтаксиса JavaScript. Проверены PowerShell по умолчанию, вывод UTF-8, кириллица, пробелы, апостроф и псевдоним в рабочем каталоге и имени файла, передача кода завершения 7. MSVC, полная нативная серверная часть на Windows и реальная интеграция Codex Desktop ещё не проверены.
- Оптимизированная Windows GNU-сборка выполнена в Docker; `sanctum-guard.exe --version` успешно запущен в Wine. Персональные пути не найдены в UTF-8 и UTF-16LE строках исполняемых файлов.
- Полный комплект Linux прошёл проверку во временном домашнем каталоге: установка, маскирование, локальное восстановление, инициализация нативного app-server и удаление.
- Пройдены форматирование Rust, Clippy с `-D warnings`, проверка синтаксиса Python, JSON и JavaScript, а также `git diff --check`.
- Все цели проверены на Rust 1.88.0 с закреплёнными зависимостями.
- Нативный патч соответствует манифесту и подготовленным исходникам upstream.
- Проверена русская справка CLI и сохранена команда `help`.
- В текущих публикуемых файлах и локальной истории Git не найдены типовые файлы авторизации, ключей и хранилищ либо персональные пути. Это не заменяет полноценную проверку на секреты.

Эти результаты не подтверждают ручные сценарии Desktop и запуск GitHub Actions.

Поддержка Windows x64 пока экспериментальная. Подготовка профиля и границы контейнерных тестов описаны в [инструкции Windows](WINDOWS.md). Готовый профиль реального Windows Desktop отсутствует; macOS не проверялась.
